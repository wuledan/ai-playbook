2. **slotstream Review 2026** (reviews, 7.6/10, body 1090 词) — carloslfu/slotstream 244★/13 forks（08-28 创建，6 天内），MIT，Swift/MLX。
   - 定位：单二进制 Swift+MLX 引擎，把 125B MoE（4-bit 105GB 磁盘）**从 SSD 流式加载**到低内存 Mac — 48GB M5 Pro 实测 warm decode ~12 tok/s、engine start ~2s（只载 3.8GB dense trunk）、峰值 32GB 自适应
   - 内存设计即产品：3.8GB trunk 常驻；routed experts（512/layer，每 token 激活 10 个）经 pread 流入全 48 层共享的固定 slot 池（7280 global slots = 20.1GB）；每 15s 检查并在请求间动态 resize，其他 app 要内存就让
   - 为什么不能 mmap：MLX 无法 materialize 部分 mmap tensor — top-10 expert gather 会 evaluate 全部 512 experts → mmap 路径加载 ~100GB 直接死；stock mlx_lm.load() 把 48GB 机器打进 swap
   - 关键工程主张：**cache 大小只影响速度不影响输出** — 4GB cache 与 24GB cache greedy decode byte-identical，且是 standing test；sweep（≥256 tokens 连续读 + grouped matmul）让 8k prompt 91→184 tok/s
   - tier 表（`slotstream doctor --sim-ram N` 可复现）：8GB→8.1GB floor ~3 tok/s（会警告 paging）/ 16GB→10GB ~4 / 24GB→16GB ~8 / 32GB→22GB ~9 / 48GB+→33GB ~12（33GB 是实测曲线 knee，34-84GB 无差别）— 只有 48GB 行是真实硬件测量
   - MTP speculative decoding：1.5GB draft head 预测下一 token（86% 正确率），两 token pass 验证 — 实测 ×1.24 decode（10.3→12.8 tok/s）、code prompt ×1.33、auto 阈值 28GB
   - 安装：curl|sh 装 ~/.slotstream/bin；`gh attestation verify` 验签；105.3GB/25 文件 sha256 内置校验 + 8 连接并行下载（1Gbps 约 16 分钟）+ 断点续传；serve :11434 兼容 Ollama/OpenAI chat 子集（curl/Open WebUI/OpenAI SDK 可用，unsupported 返回明确 400）
   - 诚实边界：Apple Silicon only（unified memory 假设，Linux/Windows 是第二个引擎且明确不在 roadmap）；**只跑一个模型** qwen3.8-flash-next:4bit（27B 是 dense 完全不同）；105GB 下载是最大门槛（512GB Mac 现实最低）；8/16/24/32GB 行是估算非实测（公开征集 measured rows）；prompt 是慢轴（8k ~39s@48GB）；0.2.0 Ollama CLI 坏了（main 已修未发版）；功耗未测
   - HN Show HN 225pt/106c（09-01）：评论区质疑领域拥挤（mlx-moe-offload/streamlx/mlx-flash/Mference/SwiftLM），作者回应加 benchmark 对比表 + 清理 README + 承诺维护；相关项目清单自曝 8 个竞品
   - 角度：vs llama.cpp（成熟但 64GB floor）、Rapid-MLX/oMLX（全驻留快几倍但要 128GB）、AirLLM（layer 级非 expert 级）、自研 MLX offload
